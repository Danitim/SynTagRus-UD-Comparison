# Текущий метод сопоставления SynTagRus и UD

Этот документ кратко описывает, как в режиме `certified` формируется итоговое сопоставление синтаксических связей между двумя корпусами.

## Цель

Метод не изменяет ни дерево SynTagRus, ни дерево UD. Он строит внешнее взаимно-однозначное соответствие между сопоставленными ребрами. В коде это представлено как частичное инъективное отображение из UD-ребер в STR-ребра:

```text
UD edge -> STR edge
```

То есть одно STR-ребро не может быть использовано для нескольких UD-ребер; на множестве уже выбранных пар это соответствует формулировке главы о частичном биективном соответствии между сопоставленными ребрами.

Сопоставление используется для последующего сравнения синтаксических связей. Поэтому важно не только получить максимальное покрытие, но и явно разделять:

- строго доказуемые соответствия;
- эвристически выбранные соответствия;
- неоднозначные или неразрешенные случаи.

## Базовая идея

Для каждого UD-ребра строится множество возможных STR-кандидатов. Кандидаты порождаются только из структуры деревьев и порядка токенов:

- совпадение токенов;
- совпадение или зеркальность ребер;
- локальная топология дерева;
- корни;
- пути и LCA;
- порядок зависимых в предложении.

Метод не использует ручную разметку, gold-набор для обучения, названия конкретных UD/SynTagRus отношений как правила сопоставления и отдельный пунктуационный слой.

## Связь с текстом главы

Текст главы описывает тот же алгоритм на более высоком уровне:

- напрямую сопоставимые случаи соответствуют `exact_same_dir`;
- зеркальные пары соответствуют `exact_mirrored`;
- соседство зеркальных совпадений соответствует `mirror_relative`;
- локальные цепочки соответствуют `strict_plus`, `head_bridge` и `mirror_swap`;
- пути к общему предку соответствуют `lca_step_N` и, на остатке, `lca_full`;
- сдвиг корня локальной конструкции соответствует `root_path`;
- обход деревьев сверху вниз соответствует `topdown`.

Дополнительные технические слои `order_residual` и опциональный `fi2003` не противоречат главе: первый нужен для покрытия и визуализации остатка, второй отключен по умолчанию и не является обязательной частью описанного метода.

## Порядок построения

### 1. Строгий слой exact-ребер

Сначала фиксируются самые надежные случаи.

`exact_same_dir`:

- в обоих деревьях есть ребро между теми же двумя токенами;
- направление головы совпадает;
- это строгое соответствие.

`exact_mirrored`:

- в обоих деревьях есть ребро между теми же двумя токенами;
- направление головы противоположное;
- это тоже строгое соответствие.

Эти два типа фиксируются до запуска любых эвристик. Они не являются эвристическими правилами.

### 2. Структурные кандидаты

После строгого слоя добавляются дополнительные кандидаты.

`mirror_relative`:

- локальное продолжение вокруг уже найденной зеркальной пары;
- нужно для случаев, где рядом с mirrored-ребром возникает цепочка или перестройка;
- использует только топологию соседних ребер.

`root_path`:

- правило для сдвига корня;
- сопоставляет UD-звезду вокруг нового корня с STR-цепочкой между старым и новым корнем.

`strict_plus`, `head_bridge`, `mirror_swap`:

- локальные структурные правила для коротких перестроек;
- покрывают случаи, где прямое ребро в одном дереве соответствует короткой цепочке или локальной замене головы в другом;
- используют только уже наблюдаемые ребра и локальные якоря, не названия синтаксических отношений.

`lca_step_N`:

- локальные LCA-кандидаты с ограниченным радиусом;
- используются как основной слой структурного расширения.

`topdown`:

- кандидаты из обхода деревьев сверху вниз.

`fi2003`:

- опциональный источник кандидатов на основе ordered-tree matching;
- по умолчанию не является обязательным, потому что может быть медленнее.

### 3. Мягкий остаточный слой

Если после структурных правил остаются UD-ребра без кандидата, добавляется `order_residual`.

Это мягкое правило:

- смотрит на глобальный порядок оставшихся зависимых;
- не делит предложение по пунктуации;
- не создает строгих соответствий само по себе;
- нужно для технического покрытия и визуализации остатка.

### 4. Полный LCA-проход на остатке

Если локальные LCA-ограничения не хватили, для оставшихся ребер добавляется `lca_full`.

Это completeness-pass: он не должен превращать сомнительные случаи в строгие автоматически, но расширяет множество кандидатов, чтобы не терять потенциально сопоставимые связи.

## Как выбирается итоговое соответствие

После построения кандидатов получается двудольный граф:

```text
UD-ребра <-> STR-кандидаты
```

Далее решается задача частичного взаимно-однозначного сопоставления. В направлении `UD -> STR` это инъективное отображение: одно STR-ребро не может быть использовано для двух разных UD-ребер.

Алгоритм работает по этапам:

1. Сначала фиксируются `exact_same_dir` и `exact_mirrored`.
2. Затем запускается constraint propagation: если у ребра остается единственный допустимый кандидат, он фиксируется.
3. Оставшиеся нерешенные ребра делятся на отдельные независимые группы. Если две группы не претендуют на одни и те же STR-ребра, их можно анализировать отдельно.
4. В каждой небольшой группе метод перебирает все варианты, которые сопоставляют максимально возможное число ребер. Если во всех таких вариантах UD-ребро получает один и тот же STR-кандидат, это соответствие считается вынужденным.
5. Если группа слишком большая для полного перебора, метод использует экономный по памяти алгоритм выбора одного хорошего варианта. Такой вариант полезен для покрытия и визуализации, но он не считается доказательством строгой корректности.

Если соответствие вынуждено структурными ограничениями, оно получает строгий статус. Если оно выбрано вторичным скором, оно помечается как эвристическое.

## Приоритет при эвристическом выборе

Когда строгого вывода недостаточно и нужен один технический вариант, используется вторичный скор.

Главный приоритет:

1. `exact_same_dir`;
2. `exact_mirrored`;
3. `mirror_relative`;
4. `root_path`;
5. остальные структурные источники;
6. мягкий `order_residual`.

Это означает: прямые и зеркальные ребра всегда сильнее любых последующих эвристик.

## Итоговые статусы

`exact_same_dir`:

- одно и то же ребро с тем же направлением;
- строгий случай.

`exact_mirrored`:

- одно и то же неориентированное ребро с противоположным направлением;
- строгий случай.

`restructured`:

- STR-ребро имеет другие вершины, но выбрано как структурный аналог;
- может быть strict, если выбор был вынужден;
- может быть heuristic, если выбор сделан вторичным скором.

`ambiguous`:

- есть несколько равноправных структурных вариантов;
- метод не делает вид, что один из них строго правильный.

`candidate_gap`:

- для UD-ребра не удалось получить осмысленный STR-кандидат после всех слоев.

`unresolved`:

- технический статус отсутствующего результата.

## Как интерпретировать результат

Для основной надежной оценки следует использовать строгие случаи:

- `exact_same_dir`;
- `exact_mirrored`;
- `restructured` с `certification = strict`.

Эвристические случаи можно использовать для:

- визуального анализа;
- поиска проблемных категорий;
- оценки потенциального покрытия;
- формирования кандидатов для ручной проверки.

Их нельзя смешивать со строгими случаями без отдельной маркировки.

## Роль папки `examples/certified/correct`

Файлы в `examples/certified/correct` используются как внутренний regression gold-set для проверки алгоритма.

Они не являются обучающими данными и не участвуют в построении сопоставления. Их задача только одна: быстро обнаружить, что изменение алгоритма сломало уже вручную проверенный пример.
